# glushko.works — личный консалтинговый сайт Даниила Глушко

## Что это
- Статический сайт. Исходник главной — `_index.html` (HTML/CSS/JS в одном файле, оба языка рядом: `<span lang="en">…</span><span lang="ru">…</span>`). Опубликованные `index.html` и `ru/index.html` собираются из него и руками не правятся.
- Хостинг: GitHub Pages, репозиторий `DaniilGlushko/glushko.works` (публичный). Эта папка — его клон.
- Домен `glushko.works` куплен через Google Workspace, DNS — в Squarespace.
- Контактная форма отправляет заявки через Web3Forms на daniil@glushko.works.

## Содержание
- Основной язык английский (`/`), русская версия — отдельная страница `/ru/`. Переключатель EN/RU переходит между ними.
- `index.html` и `ru/index.html` собирает `_build_ru.py` из `_index.html` (у русской свои title, description, OG, canonical). В каждую страницу попадает только её язык: второй вырезается `_strip_lang.py`. Раньше оба языка лежали в каждой странице и прятались CSS — для Яндекса пары страниц были почти одинаковыми, и он держал в индексе только одну (11.11.2026).
- Подстраницы `/about/`, `/press/` и их русские версии `/ru/about/`, `/ru/press/` тоже не правятся руками: их собирает `_build_pages.py` из стилей, шапки и футера `_index.html`, тоже по одному языку на страницу. Био и карьера для /about/ — в `BIO` и `CAREER`, список публикаций — в `PRESS_ITEMS` внутри скрипта. Зачем: по имени «Даниил Глушко / Daniil Glushko» сайт должен занимать несколько строк выдачи и вытеснять старые статьи.
- Фото `images/daniil-glushko.jpg` — копия портрета с именем в имени файла, для картинок по имени; не удалять.
- Страница «Фото» `/photos/` и `/ru/photos/` (с 12.11.2026) тоже собирается `_build_pages.py`: все фото владельца крупно, подписи и alt с полным именем на языке страницы. `sitemap.xml` теперь генерирует `_build_pages.py` (все страницы и их фото) — руками не править.
- Фото лежат в `images/`, пути абсолютные (`/images/...`), чтобы работали с обеих страниц.
- Портрет `portrait.jpg` всего 800×1000: показывать маленьким (не шире ~240px), иначе выглядит мыльно и растянуто.
- Дизайн (ноябрь 2026): «консалтинг + маршрут» — тёплый светлый фон, бирюза #0E3B4A и охра #D9A441, маршрут Москва–Гонконг–Манила–Бахрейн с живым временем на первом экране и один штамп «Agreed result». Шрифты (Cormorant Garamond, Golos Text, JetBrains Mono) лежат в `fonts/`, Google Fonts не используется.
- Папка `_concepts/` — локальные черновики концептов, исключена через `.git/info/exclude`, в репозиторий не попадает.
- SEO: robots.txt, sitemap.xml (обе страницы с hreflang), микроразметка schema.org в `<head>`. Сайт подтверждён в Google Search Console и Яндекс.Вебмастере (файлы `yandex_*.html` не удалять). Статистика — Cloudflare Web Analytics.
- Услуги: международные коммуникации (главное), бизнес-консалтинг, интеграция/внедрение, события, образовательная инфраструктура.
- География: Москва, Гонконг, Манила, Бахрейн.
- Позиционирование: сопровождение «до согласованного результата» — подписанная сделка, первая отгрузка, выход на маржу.
- Компании в кейсах называть только с их согласия (Росатом, MVC и др. — можно).

## Как работать
- Любая правка: изменить `_index.html` → `python3 _build_ru.py && python3 _build_pages.py` → показать владельцу, что изменилось → по подтверждению `git add`, `git commit`, `git push origin main`.
- Если меняются title/description/OG в `_index.html`, обновить их пары в списке `swaps` в `_build_ru.py` (скрипт упадёт, если не найдёт строку). GitHub Pages обновится сам за 1–2 минуты.
- Перед пушем проверять, что EN и RU версии текста правятся синхронно.
- Не менять ключ Web3Forms и адрес получателя без прямого указания.
- Не добавлять внешние скрипты/трекеры без согласования.

## Стиль
Отвечать по-русски, коротко. Тексты для сайта — тёплый деловой тон, без канцелярита и без «AI-звучания». Владелец редактирует внимательно, ждать правок.
